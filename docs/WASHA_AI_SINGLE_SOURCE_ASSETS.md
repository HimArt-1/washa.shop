# WASHA AI — Single Source Artwork Pipeline

## المبدأ

يُحفظ ناتج مزود الصور أولًا وبالبايتات نفسها كـ **Raw Source** غير قابل للتعديل، قبل إزالة الخلفية أو التحقق أو إنشاء الموكب. بعد ذلك يتفرع المسار إلى:

- **Preview branch:** يعرض موكبًا مشتقًا عندما ينجح التركيب، أو يعرض الـRaw Source نفسه عندما يتعطل مشتق المعاينة.
- **Print branch:** ينشئ `design-master.png` و`print-production.png` عندما تصبح شروط الإنتاج مستوفاة.

فشل فرع الطباعة لا يمحو نتيجة العميل ولا يحوّل التوليد الناجح إلى 422؛ ينتقل الطلب إلى `pending_prepress` مع بقاء الأصل قابلًا للعرض والاعتماد.

## المسار الجديد

1. يستقبل `/api/washa-dtf-studio/generate-mockup` فكرة العميل والاختيارات المنظمة.
2. يبني الخادم برومبت Artwork معزولًا ويطلب من GPT Image:
   - `output_format=png`
   - `background=transparent`
   - `quality=high`
3. تُفحص بايتات المزود للتأكد من أنها صورة PNG/JPEG/WebP سليمة، ثم تُحفظ فورًا في `washa_design_source_assets` مع SHA-256 وأبعادها وحالة خلفيتها وبيانات المزود.
4. يبدأ تجهيز نسخة الطباعة عبر Sharp: PNG، Alpha حقيقية، بكسلات شفافة، مساحة آمنة، دقة وحدود سليمة.
   كما تُرفض لوحة خلفية معتمة داخل هامش شفاف، ويُفحص الـeffective DPI مقابل مقاس الطباعة الفعلي.
   وعند وجود `calligraphyText` صريح، يمر الناتج بتحقق OCR عربي مطابق حرفيًا قبل القبول.
5. عند نجاح التجهيز يُحسب SHA-256، ثم يُرفع مرة واحدة إلى:
   `washa-design-assets/design-masters/{profileId}/{masterAssetId}/design-master.png`
6. يُعاد تنزيل الملف فورًا وتُقارن بصمته قبل تسجيله في `washa_design_master_assets`.
   الـbucket خاص، والروابط الدائمة تمر عبر `/api/washa-dtf-studio/assets/...` مع تحقق المالك أو فريق الإنتاج.
7. يبحث resolver عن مرجع يطابق المنتج واللون والجهة في `washa_garment_mockup_assets`.
8. عند غياب المرجع المطلوب، يولّد المزود قطعة فارغة فقط ويحفظها كـ `generated_blank_garment`.
   قبل التخزين تُفحص الدقة واللون، ثم يتحقق نموذج رؤية من نوع القطعة واللون والجهة وخلوها من أي شعار/نص، ويعيد print area normalized للتركيب.
9. يركب Sharp نفس `design-master.png` على القطعة باستخدام `placement_data`. إذا فشل مشتق الموكب بعد اكتمال الـmaster، يرجع الـRaw Source المحفوظ بدل 5xx ويبقى ملف الطباعة جاهزًا.
10. عند تعذر الشفافية الآمنة أو تعطل خدمة تحقق مساندة، يعاد الـRaw Source بحالة `pending_prepress`. يستطيع العميل اعتماد النتيجة، وتُثبت بصمتها في revision/order دون ادعاء أنها جاهزة للطباعة.
11. عند الاعتماد الجاهز، ينشئ `washa_design_revisions` و`print-production.png` من الـmaster نفسه فقط.
   تسجل مشتقات الإنتاج بصمتها الخاصة، ويعاد التحقق من revision/master/derivative وبصماتها عند إكمال الطلب وتنزيل الإنتاج.
12. تغيير القطعة أو الجهة أو الموضع يستدعي `/api/washa-dtf-studio/recompose-preview` فقط عندما يوجد master جاهز، ولا يستدعي مزود Artwork ولا يستهلك توليدًا جديدًا.

## Prompt Native / DEV V3

المسار الداخلي `/design/washa-ai/dev-v3` يحافظ على عقدة الأصل الواحد نفسها، لكنه يستخدم خط إنتاج مستقلًا:

1. يثبت الخادم نموذج Artwork على `gpt-image-1.5` ويطلب `PNG` مع `background=transparent` وAlpha حقيقية.
2. يستدعي مزود Artwork مرة واحدة فقط، ثم يعيد بايتاته فورًا إلى خدمة الحفظ دون تحقق مسبق أو إعادة توليد مخفية.
3. يحفظ الخادم البايتات نفسها كـRaw Source غير قابل للاستبدال، ثم ينشئ `design-master.png` كمشتق منفصل عبر المعالجة المحلية والتحقق المعتاد.
4. ينشئ الخادم Placement Guide حتميًا داخل مساحة الطباعة الآمنة، ثم يرسل الموكب المختار كمرجع A، وأصل الطباعة غير القابل للتعديل كمرجع B، ودليل الموضع كمرجع C إلى `gemini-3.1-flash-image`. إذا كانت نسبة الموكب غير قياسية، يضيف padding مرآتيًا مؤقتًا ثم يقص الناتج ويعيده حتميًا إلى أبعاد وإطار المصدر الأصليين.
5. يسمح Gemini فقط بالتحويل الهندسي والتفاعل البصري مع طيات القماش؛ لا يُسمح بإعادة رسم النص أو الألوان أو عناصر التصميم.
6. تمر نتيجة الموكب عبر بوابة رؤية مستقلة تقارنها بالمراجع الثلاثة، وتتحقق من وجود التصميم وهويته ونصه والقطعة والموضع والتأطير. إذا فشل الموكب يبقى الـRaw Source محفوظًا ومعروضًا ولا تضيع نتيجة التوليد.
7. يتحقق الخادم من جاهزية مفتاحي OpenAI وGemini لهذا الخط قبل الحصة أو التوليد، ولا تؤثر أعطاله في قاطع دائرة النسخة الرسمية.
8. تُرفض أي overrides تستبدل نماذج الشفافية أو التركيب أو التحقق بنماذج خارج allowlist المعتمدة.
9. لا يستطيع العميل تشغيل هذا الخط بإرسال `pipeline` يدويًا؛ الخادم يفعّله حصريًا لطلبات نفس النطاق القادمة من `DEV V3`.

لا يُستدعى نموذج الصور مرة ثانية لإصلاح الخلفية. إذا تعذر بناء master آمن محليًا، تصبح النتيجة `pending_prepress` ويثبت الاعتماد والطلب هوية الـRaw Source وبصمتها، بينما تظل إجراءات الإنتاج والتنزيل محجوبة حتى يكتمل التجهيز.

تستخدم V3 إعداد الوصول نفسه الخاص بـV2، وتبقى النسخة الرسمية والمسارات التطويرية السابقة على خط Sharp القياسي بلا تغيير.

إذا فشل مشتق المعاينة بعد حفظ الـmaster، يعرض النظام الـRaw Source ويبقي حالة الإنتاج `ready`. وإذا فشل تجهيز الطباعة قبل إنشاء الـmaster، يعرض المصدر بحالة `pending_prepress`. إعادة المحاولة بالمعرّف نفسه تستعيد المصدر أو الـmaster المحفوظ ولا تعيد توليد Artwork.

## الجداول

- `washa_design_source_assets`: بايتات المزود الأصلية immutable مع البصمة والتشخيص وبيانات التوليد.
- `washa_design_master_assets`: نسخة الطباعة المجهزة، مرتبطة بالـRaw Source الذي اشتقت منه.
- `washa_garment_mockup_assets`: Manifest المراجع والقطع الفارغة المولدة لكل لون/جهة.
- `washa_design_asset_derivatives`: thumbnails/previews/mockups/print-production وعلاقتها بالأصل.
- `washa_design_requests`: الطلب الجاري، الـRaw Source، الـmaster الاختياري، الموضع ونوع المعاينة.
- `washa_design_revisions`: لقطة اعتماد immutable؛ يمكن أن تكون `ready` أو `pending_prepress` مع source مثبت.
- `custom_design_orders`: يثبت `design_source_asset_id` و`source_checksum`. الإصدار الجديد `asset_schema_version=2`، والطلبات القديمة تبقى كما هي.

## قواعد التوافق

- الطلبات القديمة لا تُعدّل أصولها ولا تُعاد توليدها.
- تُرقّى masters القديمة إلى سجلات Source توافقية تحمل `legacy_promoted_master=true`؛ لا تُوصف على أنها بايتات مزود خام لم تكن النسخة القديمة تحفظها.
- مسار Base64 القديم في `submit-order` يبقى للقراءة/الإرسال القديم فقط ويُسجّل كـ `legacy_unverified`.
- استخراج التصميم من الموكب معطل افتراضيًا. يمكن تفعيله مؤقتًا فقط عبر:
  `WASHA_DTF_LEGACY_EXTRACTION_ENABLED=true`
- الواجهة الجديدة لا تستدعي الاستخراج التوليدي ولا إزالة الخلفية.

## تطبيق migration

طبّق:

1. `supabase/migrations/20260716120000_washa_ai_single_source_assets.sql`
2. `supabase/migrations/20260722233000_washa_ai_raw_source_pipeline.sql`

ينشئ migration bucket خاصًا `washa-design-assets` والجداول والقيود والـRLS وManifest أولي من صور الألوان والمقاسات الحالية. لا يفترض أن مرجع الأمام صالح للخلف.

مراجع `ai_reference_front_url/back_url` القديمة تُسجل كسجلات Manifest غير فعالة لأنها غير مرتبطة بلون مؤكد. لا تدخل المسار حتى يربطها المشرف بلون مطابق ويفعّلها.

## اختبار E2E حي

`npm run qa:washa-single-source`

يتطلب بيئة staging ومستخدمًا مصادقًا ومتغيرات `WASHA_E2E_*`. ينفذ توليدًا حقيقيًا، يجلب الأصل الخاص، يطابق SHA-256، ثم يغيّر الموضع عبر recompositing ويتأكد أن `masterAssetId` و`masterChecksum` لم يتغيرا.
